# Устранение неполадок

## Приложение

### Нет уведомления о прогрессе транскрипции

Для приложения **заблокированы уведомления** (типично для Samsung: Настройки → Приложения → VoiceScribe → Уведомления → «Разрешить уведомления»). FGS-сервис при этом работает, но уведомление не показывается. Это **не** причина сбоев транскрипции — только отсутствие индикатора прогресса.

### Приложение вылетает при старте

1. Проверьте logcat: `adb logcat -d | grep -i "voicescribe\|sherpa\|FATAL"`.
2. Типовые причины:
   - **Повреждённая база Room** — удалите данные приложения (Настройки → Приложения → VoiceScribe → Память → Очистить данные) или `adb shell pm clear com.example.voicescribe`.
   - **Несовместимое устройство/ABI** — приложение содержит 4 ABI (arm64-v8a, armeabi-v7a, x86, x86_64); на 32-битных системах без NEON производительность будет низкой.

## Модели

### Скачивание не начинается или падает

- Модели скачиваются с GitHub releases k2-fsa. Проверьте соединение и что домен не заблокирован (VPN/корпоративная сеть).
- Whisper medium (~1.9 ГБ) требует стабильного интернета и свободного места во внутреннем хранилище.
- После скачивания проверяется SHA-256; несовпадение → ошибка → повторная попытка скачивания.

### Модель скачана, но транскрипция «пустая»

- Проверьте вкладку **«Модели»**: файлы могут быть помечены как установленные при пустой директории (известная проблема: распакованная директория pyannote была пустой, хотя запись в БД существовала). **Удалите модель и скачайте заново.**
- VAD-модель называется `silero_vad_v5.onnx` (не `silero_vad.onnx`). Если файл отсутствует — `SherpaVadEngine` бросит `VadException`, и пайплайн автоматически переключится на фиксированные чанки по 30 с (пустая транскрипция невозможна).

### GigaAM не распознаёт или ошибка при загрузке

- GigaAM v3 (RU) — официальный релиз k2-fsa, работает как обычная модель каталога.
- GigaAM Multilingual — community-конвертация с HuggingFace (без официальной записи в checksum.txt k2-fsa). Если SHA-256 на сервере изменится — скачивание упадёт с ошибкой контрольной суммы; удалите модель и дождитесь обновления приложения или скачайте повторно.

### Как проверить файлы моделей вручную

```bash
adb shell "ls -la /data/data/com.example.voicescribe/files/models/"
```

(на не-rooted устройстве вывод может быть ограничен; используйте `run-as com.example.voicescribe ls files/models/` на debug-сборке)

## Транскрипция

### Результат на английском при выборе русского

- **AUTO**: если определение языка вернуло пустую строку — Whisper определяет язык по каждому чанку сам. На коротких файлах или с сильным акцентом возможны ошибки; выберите язык вручную.
- **Ручной выбор RU**: проверьте, что выбрали язык **до** запуска. Кэш распознавателя ключуется по `modelId|lang` — старые сборки «запекали» язык первого запуска; переустановите свежий APK, если поведение сохраняется.

### Долгая транскрипция

- CPU-only (ARM NEON). Ожидаемо: tiny быстрее base, base быстрее medium; длинные файлы + диаризация сильно увеличивают время.
- Прогресс отображается по этапам: подготовка → декодирование → VAD/диаризация → распознавание.

### Задача «застряла» в активном состоянии (SUBMITTED/DECODING/…)

Приложение при старте помечает задачи, брошенные после убийства процесса, как `FAILED` (`reconcileStaleJobs`). Если карточка не обновилась — перезапустите приложение.

## Устройство / отладка

### Где файловый лог приложения

Вкладка **«Настройки»** → включите «Логирование в файл» и выберите уровень (по умолчанию выключено). Журнал пишется в `filesDir/logs/voicescribe.log` (ротация при 5 МБ). Доступ к файлу:

```bash
adb shell run-as com.example.voicescribe ls files/logs/
adb shell run-as com.example.voicescribe cat files/logs/voicescribe.log
```

Перед воспроизведением проблемы включите логирование и выберите «Отладка» — это даст полный стек этапов транскрипции.

### `adb` не найден в PATH

Используйте MCP-инструменты `android_*` (они поставляют собственный adb/scrcpy) или добавьте `platform-tools` в PATH.

### Сборка на Windows падает на путях с кириллицей

`C:\Users\Администратор\...` — AGP отказывается собирать без `android.overridePathCheck=true` в `gradle.properties` (уже выставлено в репозитории). SDK вынесен в ASCII-путь `C:\AndroidSdk` намеренно.

### Полный цикл проверки на устройстве

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.example.voicescribe/.ui.MainActivity
adb logcat -d > logcat.txt          # анализ после прогона
adb shell am force-stop com.example.voicescribe
```
